# MindRail v0.1 Roadmap

> **Roadmap only.** Nothing in this file proves that a capability exists. See `docs/CURRENT_STATE.md` for current reality.

The v0.1 objective is a minimal, usable control-plane reference that one maintainer can dogfood with real agents without locking the protocol to a specific vendor.

## Slice 0 — Development foundation

**Status:** implemented, verified, and merged.

- authoritative repository documentation;
- ADR workflow;
- BSL/source-available licensing foundation;
- agent/contributor workflow;
- TypeScript quality baseline;
- GitHub CI and review templates.

Repository-level required branch protection remains tracked separately in issue #3.

## Slice 1 — Domain contracts

**Status:** implemented, verified, and merged.

Canonical JSON Schema Draft 2020-12 contracts and generated TypeScript bindings define the stable v1 domain vocabulary:

- Workspace;
- Goal;
- Task;
- Agent;
- Session;
- Lease;
- Checkpoint;
- PermissionRequest / PermissionDecision;
- AuditEvent.

The slice includes strict schema validation, representative positive/negative fixtures, deterministic generated bindings, and generated-drift detection.

## Slice 2 — Control-plane protocol

**Status:** v0.1 command surface implemented and verified; durable command/query composition remains intentionally partial.

ADR-0005 defines the transport-neutral command/query semantics, idempotency scope, fencing/revision authority, recovery behavior, error model, and HTTP/MCP mapping principles.

The canonical runtime/application command surface implements all ADR-0005 v0.1 commands, including Agent registration and Session bootstrap, lifecycle/recovery, permission request/decision, cancellation, and idempotent replay. Durable composition now covers the complete ADR-0005 v0.1 command surface, including `RetryTask`, `CancelTask`, and `CancelGoal`. Database-enforced mutation guards preserve receipt atomicity, Goal-versus-Task admission ordering, and cancellation-versus-recovery fencing under the SQLite D1-like reference harness.

Durable read/query support now includes single-resource execution/permission reads, checkpoint and permission-decision history, the pending-human queue, and advisory claimable work. `ListGoals`, `ListGoalTasks`, and `GetTaskExecutionView` remain pending.

## Slice 3 — Local reference runtime

**Status:** in-memory lifecycle/permission runtime and first durable application composition implemented and verified locally.

Implemented behavior includes:

- Agent registration and Session bootstrap/liveness/end;
- Goal/Task lifecycle and dependency release;
- claim/release/recovery and Lease renewal semantics;
- one effective Lease in the local runtime;
- monotonic per-Task fencing and stale-executor rejection;
- Checkpoints and completion/failure/block/resume/retry;
- Task/Goal cancellation and Lease revocation;
- deterministic permission policy plus human `HUMAN_REQUIRED` follow-up;
- in-memory protocol idempotency with immutable replay snapshots;
- runtime snapshot rehydration from canonical durable state;
- a durable dispatcher that reloads authoritative state for every supported command rather than retaining an in-memory fallback;
- atomic durable receipts for the first command loop, including deferred `ClaimTask` receipt construction from the persistence-allocated fencing token;
- durable queries for `GetWorkspace`, `GetGoal`, `GetTask`, `GetLease`, `GetAgent`, `GetSession`, `GetPermissionRequest`, `ListTaskCheckpoints`, `ListPendingHumanPermissions`, `ListPermissionDecisions`, and advisory `ListClaimableTasks`;
- HTTP E2E evidence for restart-after-claim, restart-after-`HUMAN_REQUIRED`, response-loss replay, competing claims, and monotonic fencing recovery against the SQLite D1-like test harness.

Durable Session/Lease liveness is now covered through HTTP restart E2E: heartbeat does not extend Lease authority, renew preserves the fence, release permits higher-fence recovery, and EndSession durably revokes active Lease authority before recovery. Durable lifecycle/cancellation command parity is complete locally; remaining local work is bounded query parity plus persistence-concurrency hardening and final end-to-end reconciliation. The executed SQLite/D1-like tests do not substitute for deployed Cloudflare verification.

## Slice 4 — GitHub integration

**Status:** planned.

Add the first repository/task/config integration without making GitHub a core protocol dependency.

## Slice 5 — Cloudflare reference deployment

**Status:** persistence adapter plus first durable application composition implemented and verified locally; deployed reference runtime still pending.

The reference direction remains one Workspace Durable Object coordinator plus shared D1 durable state, with Cloudflare primitives outside canonical domain/protocol contracts. The adapter has executable tests for idempotency, fencing/concurrency, permission-head integrity, persistence invariants, canonical state rehydration, durable command replay, query reads, and restart/concurrency semantics through HTTP using the SQLite D1-like harness.

Next: deploy the existing composition on real Cloudflare Workers/Durable Objects/D1, verify environment/migrations plus deployed restart/concurrency behavior, and only then make Cloudflare-runtime claims.

## Slice 6 — Agent integrations

**Status:** generic HTTP/MCP transport boundary and durable work-acquisition read path implemented; real agent-host integrations planned.

Implemented foundation:

- bounded HTTP adapter;
- bounded MCP adapter without generic shell/filesystem/browser/action authority;
- canonical Agent registration / Session bootstrap commands;
- durable HTTP composition for the first autonomous execution loop;
- advisory `ListClaimableTasks` for both new `ready` work and `running` recovery work without effective Lease authority, with atomic authority revalidation at `ClaimTask`.

Still required for v0.1 dogfooding:

- Codex bootstrap/integration path;
- ChatGPT-compatible web/app path where platform capabilities allow it;
- real generic MCP/HTTP agent loop that acquires work, checkpoints, and requests decisions;
- tolerance for host platforms interrupting or terminating sessions.

## Slice 7 — Human/project projections

**Status:** planned.

Add optional human-facing projections such as Google Sheets or a lightweight UI only after runtime state is durably composed. Projections are not authoritative storage.

## v0.1 success condition

A user can give a goal to a supported real agent, the agent can obtain a **durable** task/context/policy assignment from MindRail, report checkpoints and evidence, continue to the next action without asking the user by default, and escalate only when a policy/decision boundary requires human input.

**Current gap to that condition:** at least one real agent-host integration, the three remaining durable read queries, persistence/deployed-reference-runtime hardening, and real Cloudflare verification are outstanding. The local durable HTTP composition now proves the command-side persistence/restart contract, but it is not yet a real-agent or deployed-Cloudflare product path.
