# MindRail v0.1 Roadmap

> **Roadmap only.** Nothing in this file proves that a capability exists. See `docs/CURRENT_STATE.md` for current reality.

The v0.1 objective is a minimal, usable control-plane reference that one maintainer can dogfood with real agents without locking the protocol to a specific vendor.

## Slice 0 — Development foundation

**Status:** implemented, verified, and merged.

- authoritative repository documentation;
- ADR workflow;
- BSL/source-available licensing foundation;
- agent/contributor workflow;
- TypeScript quality baseline;
- GitHub CI and review templates.

Repository-level required branch protection remains tracked separately in issue #3.

## Slice 1 — Domain contracts

**Status:** implemented, verified, and merged.

Canonical JSON Schema Draft 2020-12 contracts and generated TypeScript bindings define the stable v1 domain vocabulary:

- Workspace;
- Goal;
- Task;
- Agent;
- Session;
- Lease;
- Checkpoint;
- PermissionRequest / PermissionDecision;
- AuditEvent.

The slice includes strict schema validation, representative positive/negative fixtures, deterministic generated bindings, and generated-drift detection.

## Slice 2 — Control-plane protocol

**Status:** protocol semantics accepted; executable subset implemented in the local runtime.

ADR-0005 defines the transport-neutral command/query semantics, idempotency scope, fencing/revision authority, recovery behavior, error model, and HTTP/MCP mapping principles.

The current local dispatcher implements the first execution loop commands: Goal/Task creation, claim, checkpoint, completion/failure, retry, and Task/Goal cancellation. Remaining v0.1 commands are completed as the corresponding runtime capabilities land.

## Slice 3 — Local reference runtime

**Status:** first executable vertical slice implemented and verified; durability and permission handling remain.

Implemented in-memory behavior includes:

- Goal/Task lifecycle and dependency release;
- Agent/Session execution identity for the current loop;
- claim/release/recovery semantics;
- one effective Lease in the local runtime;
- monotonic per-Task fencing;
- stale-executor rejection;
- Checkpoints and completion/failure;
- explicit retry;
- Task/Goal cancellation and Lease revocation;
- in-memory protocol idempotency with immutable replay snapshots.

Next within this slice: remaining Session/Lease lifecycle commands, permission request/decision runtime, persistence interfaces, durable command receipts/audit state, and restart-recovery tests.

## Slice 4 — GitHub integration

**Status:** planned.

Add the first repository/task/config integration without making GitHub a core protocol dependency.

## Slice 5 — Cloudflare reference deployment

**Status:** persistence architecture designed; implementation planned.

The accepted reference direction is one Workspace Durable Object coordinator plus shared D1 durable state, while keeping Cloudflare primitives outside canonical domain/protocol contracts. Implementation must independently prove transaction, fencing, idempotency, cancellation, and restart semantics before this slice is called operational.

## Slice 6 — Agent integrations

**Status:** planned.

Provide minimal bootstrap/integration paths for:

- Codex;
- ChatGPT-compatible web/app flows where platform capabilities allow it;
- generic MCP clients;
- generic HTTP clients.

The system must tolerate agents whose host platform can interrupt or terminate a session.

## Slice 7 — Human/project projections

**Status:** planned.

Add optional human-facing projections such as Google Sheets or a lightweight UI only after the runtime state model is durable. Projections are not authoritative storage.

## v0.1 success condition

A user can give a goal to a supported agent, the agent can obtain a durable task/context/policy assignment from MindRail, report checkpoints and evidence, continue to the next action without asking the user by default, and escalate only when a policy/decision boundary requires human input.
